# HUMO Card → finance collector

Отдельный обработчик использует уже подключённую Pyrogram-сессию **только** владельца
`FINANCE_OWNER_TG_ID`. Принимает входящий текст только от peer/sender `856254490`.
Другие чаты, Telegram Reader, команды аккаунта и прочие банки этим модулем не обрабатываются.
Модуль не отправляет сообщения в банк и не меняет состояние прочтения чата.

## Включение на одном Docker-хосте с finance-bot

В закрытом `.env` (права 600):

```dotenv
COMPOSE_FILE=docker-compose.yml:docker-compose.finance.yml
FINANCE_BRIDGE_ENABLED=true
FINANCE_OWNER_TG_ID=<OWNER_TG_ID финансового бота>
FINANCE_COLLECTOR_URL=http://finance-bot-api-1:8080/v1/notifications
FINANCE_COLLECTOR_TOKEN=<COLLECTOR_TOKEN финансового бота>
FINANCE_BACKFILL_DAYS=3
```

Дополнение Compose подключает userbot к существующей сети `finance-bot_default`.
Сначала поднимите finance-bot, затем пересоберите userbot обычным `docker compose up -d --build`.
Новый Telegram-вход или копирование сессии не требуются. Для отключения: переменная
`FINANCE_BRIDGE_ENABLED=false` и пересоздание контейнера. Очередь останется на диске.

## Доставка и история

Первый запуск читает последние 3 дня только банковского чата. Затем раз в минуту
догружает пропуски от сохранённого курсора, максимум за последние 30 дней (ограничение
финансового API). Курсор обновляется лишь после завершённого обхода; live-события
не продвигают его. Лимит обхода — 10 000 сообщений; при превышении курсор сохраняется
и пишется ошибка, без молчаливого пропуска истории. FloodWait учитывается отдельно.

Данные сначала записываются в `data/finance_bridge.sqlite3` (SQLite WAL, права 600).
Очередь повторяет отправку после сетевых ошибок, 401/403/429/5xx с задержкой до 5 минут.
HTTP 400/413/422 остаются как `rejected` для разбора. При HTTP 200 проверяется статус
ответа; `unrecognized`/`needs_account` означают, что исходник сохранён финансовым ботом.
Ключи сообщений стабильны: повтор после сбоя между записью на сервере и ответом
не создаёт новую операцию. После подтверждения тело удаляется из очереди; для
отклонённых запросов очищается через 30 дней. Число попыток и статус сохраняются.

При изменении/удалении банковского сообщения уже записанная операция автоматически
не исправляется. Первоначальный текст сохраняется на финансовом сервере на 30 дней;
неизвестные карты и форматы доступны там через `/pending`.

Проверка на VPS без вывода ключей и банковских текстов:

```sh
docker exec gemini_userbot python -c 'from pathlib import Path; from src.finance_bridge.outbox import Outbox; o=Outbox(Path("data/finance_bridge.sqlite3")); print(o.stats()); print("cursor", o.get_cursor())'
```

Не публикуйте `.env`, файлы сессий или SQLite. Резервная копия `data` должна включать
очередь; согласованную копию SQLite делайте через `sqlite3.Connection.backup()`.
